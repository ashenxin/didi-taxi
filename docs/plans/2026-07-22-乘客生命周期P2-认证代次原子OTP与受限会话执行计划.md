# 乘客账号生命周期 P2：认证代次、原子 OTP 与受限会话执行计划

## 1. 阶段目标与状态

P2 把 P1 的生命周期运行内核接到账户认证边界，建立数据库权威认证代次、
按用途隔离的原子 OTP、普通/受限会话、注销栅栏和保持 `customer.id` 不变的换号事务。

**当前状态：已完成。** passenger 与 passenger-api 已使用 `auth_epoch + scope`
校验 HTTP/WS 会话；换号与注销底层 Application Service 已成为 P7 公开入口的基础。

## 2. 明确边界

- P2 建立底层能力，但当时不开放新的公开 lifecycle Controller。
- 旧 settings 流量在 P2 不切入完整 Saga，正式入口迁移属于 P7。
- OTP 在 Redis 中原子消费，账户状态和 Operation 在 MySQL 本地事务中提交。
- OTP 一旦消费不能因数据库失败而恢复；用户需要重新获取验证码。
- `auth_epoch` 是数据库权威事实，Redis 不再决定 Token 是否有效。
- 注销 P2 只建立账号栅栏，不在本阶段调用 Order、Calculate 或 Wallet。

## 3. 数据库权威认证代次

每次成功登录、登出、换号、注销建栅栏和注销最终完成，都按业务语义推进
`customer.auth_epoch`。

JWT 固定包含：

- `sub`：customerId
- `ae`：认证代次
- `scope`：`NORMAL` 或 `LIFECYCLE_RESTRICTED`
- `audit`：渠道审计代次
- `operationNo`：受限会话绑定的生命周期操作

每次 HTTP 请求和 WS 握手都向 passenger 查询权威认证状态。下游认证状态不可用时
返回 503，不能因为缓存缺失而放行。

## 4. 原子 OTP

OTP 按 Purpose 隔离：

- 登录短信
- 新手机号验证
- 注销确认

Key 同时绑定必要的手机号、customerId 和 `lifecycleVersion`。验证码消费由 Lua
一次完成比较、删除和结果返回，并发请求最多只有一个得到 `CONSUMED`。

发送频率控制和验证码本体分离，不能使用 `GET -> 比较 -> DELETE` 的非原子流程。

## 5. 会话模型

### 5.1 普通会话

`ACTIVE + NORMAL` 可以访问普通业务。

### 5.2 注销受限会话

注销栅栏成功后：

- customer 进入 `CANCELLING`。
- `lifecycle_version` 和 `auth_epoch` 增加。
- 绑定 `current_lifecycle_operation_no`。
- 原 NORMAL Token 与既有 WS 会话立即失效。
- BFF 可以签发绑定 Operation 的 `LIFECYCLE_RESTRICTED` Token。

受限会话只允许查询订单、取消订单、支付欠款、查询资料、退出和管理本次注销；
不能下单、领券、签到、签约免密或发起换号。

## 6. 注销栅栏事务

固定顺序：

1. 校验幂等键和请求摘要。
2. 原子消费绑定 expected lifecycle version 的注销 OTP。
3. 生成 P1 生命周期快照并取得 operationNo。
4. 对 customer 执行 lifecycle version CAS，进入 `CANCELLING`。
5. 在同一 MySQL 事务写 Operation、Step、Event、Outbox。
6. 将 Operation 推进为 `FENCED` 并记录 restricted auth epoch。

customer、Operation、Step、Event、Outbox 任一写入失败时数据库整体回滚，但 OTP
保持已消费。

## 7. 同身份换号事务

换号始终更新原 customer 记录：

- `customer.id` 不变。
- 更新手机号。
- `lifecycle_version` 和 `auth_epoch` 增加。
- 旧手机号绑定历史变为 `REPLACED`。
- 新手机号形成 ACTIVE 绑定历史。
- PHONE_CHANGE Operation、Step、Event、Outbox 在同一事务完成。

换号与注销使用同一 `expectedLifecycleVersion` 竞争，发生并发时只能一方 CAS 成功。

## 8. 内部接口与安全

passenger 提供内部认证状态与登出接口，受 `PASSENGER_INTERNAL_TOKEN` 保护。

非 `local/dev/test` 环境必须拒绝：

- Token 缭乱、过短或缺失。
- 包含 `change-me` 的开发值。
- 不符合三端 audience 隔离的 JWT 配置。

路径认证必须基于规范化 PathPattern，防止分号、编码斜杠和多重编码绕过。

## 9. 实施任务

### 任务 1：建立原子 OTP 组件

- 定义 Purpose、Subject、Key Factory 和 Lua 消费结果。
- 覆盖用途串用、版本变化、并发消费和过期验证码。

### 任务 2：建立 auth epoch 和权威认证状态

- 登录与登出通过数据库 CAS 推进 epoch。
- ACTIVE/CANCELLING/CANCELLED 返回不同允许状态和 scope。
- 旧请求不能覆盖更新后的新会话。

### 任务 3：保护 passenger 内部入口

- 增加内部认证 Filter 和启动校验。
- 提供认证状态查询与登出接口。
- 对特殊路径编码和矩阵参数进行安全测试。

### 任务 4：切换 passenger-api JWT、HTTP 和 WS

- JWT 从 Redis token version 切换到 `ae + scope`。
- HTTP 与 WS 都查询 passenger 权威状态。
- 受限 Token 禁止 WS 和普通写操作。

### 任务 5：重接登录、登出和本节点 WS 撤销

- 登录签发当前 epoch 的 NORMAL Token。
- 登出先推进数据库 epoch，再执行后续订单清理。
- 换号或注销后关闭本节点已建立的 WS 会话。

### 任务 6：实现注销建栅栏 Application Service

- 复用 P1 Snapshot Factory 和 Store。
- 在一个数据库事务中完成 customer CAS 和运行记录持久化。
- 对幂等重放、请求摘要冲突和部分写失败进行验证。

### 任务 7：实现同 `customer.id` 换号事务

- 新手机号唯一性检查。
- 绑定历史、Operation 和账户更新原子提交。
- 验证换号/注销并发只有一方成功。

### 任务 8：配置、指标与旧认证路径清理

- 删除 Redis token version 权威路径。
- 增加认证状态查询、JWT 拒绝、OTP 消费、epoch 推进、受限 Token 和 WS 关闭指标。
- 指标标签只允许枚举值，禁止 customerId、手机号、operationNo 和异常 message。

## 10. 验收结果

已经具备以下验证：

- 同一 OTP 并发只能消费成功一次，Purpose 之间不能串用。
- lifecycle version 变化后旧换号/注销 OTP 失效。
- Redis 缺失不改变认证裁决；passenger 不可用时失败关闭。
- epoch 增加后旧 HTTP/WS Token 被拒绝。
- 受限 Token 不能访问普通写接口或申请 WS Token。
- 注销栅栏部分写失败时数据库五类状态整体回滚。
- 换号保持 `customer.id`，绑定历史正确。
- 换号与注销并发只有一个 lifecycle version CAS 成功。
- 主代码已无 `PassengerTokenVersionStore`、`passenger:tv:` 和旧 OTP 非原子成功路径。

当前 passenger 与 passenger-api 全量回归继续覆盖 P2，最近一次分别为 177 和 174
个测试通过。

## 11. 上线与回滚

上线顺序：

1. 配置 passenger 与 passenger-api 共用的 `PASSENGER_INTERNAL_TOKEN`。
2. 先部署 passenger。
3. 再部署 passenger-api。
4. 强制旧 Token 重新登录，观察 401、403、503 和认证状态查询延迟。

禁止回滚：

- 降低数据库 `auth_epoch`。
- 恢复已经失效的旧 Token。
- 重新把 Redis token version 设为权威。
- 把已经建立的注销 Operation 交回旧逻辑执行。

## 12. 完成定义

- 数据库 epoch 是 HTTP/WS 统一权威。
- OTP 按用途和 lifecycle version 原子消费。
- NORMAL 与 LIFECYCLE_RESTRICTED 权限严格隔离。
- 注销栅栏和换号事务复用 P1 运行快照。
- 换号保持 customer.id，注销栅栏进入 CANCELLING。
- 没有在 P2 提前接管完整注销 Saga。
