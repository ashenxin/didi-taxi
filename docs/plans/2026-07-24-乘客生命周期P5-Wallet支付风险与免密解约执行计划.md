## 2. 冻结步骤

| stepCode | 类型 | 语义 |
|---|---|---|
| `WALLET_FINAL_CHECK` | 同步最终检查 | 建立 Wallet 本地注销栅栏，检查支付处理中、结果确认中和重复成功等资金风险 |
| `WALLET_CLOSE_AUTO_PAY` | 必须动作 | 幂等关闭当前乘客全部未关闭免密协议；渠道结果未确认时返回 `UNKNOWN` |

预检只读，不改投影、不写参与者 Inbox。正式最终检查必须把 Passenger 的
`CANCELLING + lifecycleVersion + operationNo` 应用到 Wallet 本地投影后再做当前读。

## 3. 当前资金事实口径

- `PAYING/CONFIRMING/PROCESSING`：阻断，动作 `WAIT_OR_QUERY_PAYMENT`。
- `DUPLICATE_SUCCESS`：人工风险，阻断，动作 `CONTACT_OPERATIONS`。
- `SUCCESS/FAILED/CANCELLED`：支付尝试本身不阻断。
- 当前系统没有退款、拒付、争议实体，P5 不伪造查询；未来新增事实表时扩展 Wallet 风险查询，不修改 Passenger 主流程。
- 支付、协议和解约审计记录永久保留。

## 4. 写门禁

| Wallet 写操作 | ACTIVE | CANCELLING | CANCELLED |
|---|---|---|---|
| 新签免密、设默认免密 | 允许 | 拒绝 | 拒绝 |
| 用户主动关闭免密 | 允许 | 允许消解存量 | 允许幂等回放 |
| 创建既有欠款支付尝试 | 允许 | 最终检查 PASS 前允许；PASS 后拒绝 | 拒绝 |
| 查询、确认既有支付结果 | 允许 | 允许 | 允许 |
| 生命周期免密解约 | 禁止普通入口 | 仅当前 operation 允许 | 仅幂等查询/人工处置 |

默认模式为 `SHADOW`；P6 接通持续 ACTIVE/CANCELLING/CANCELLED 投影并完成覆盖率核验前不切 `ENFORCE`。
生命周期免密解约动作自身始终强校验当前 operation，不受影子模式放宽。

## 5. 渠道成功未知与人工处置

- 每份协议以 `operationNo + stepCode + agreementId` 保存一条解约审计。
- 本地 mock 渠道可同步确认成功；未接真实渠道时只能落 `UNKNOWN`，不得关闭本地协议。
- 同一参与者命令重复调用只返回原 Inbox 结果，不重复调用渠道。
- `UNKNOWN` 必须通过结果查询或有 actor/reason/evidence 的内部人工处置解决。
- 人工确认只能把对应协议置为 `CLOSED`，并永久记录处置人、原因、凭证和时间。

## 6. 数据表

- `wallet_account_lifecycle_event_inbox`
- `wallet_account_lifecycle_projection`
- `wallet_lifecycle_participant_inbox`
- `wallet_auto_pay_termination`

投影事件以 `sourceEventId` 永久去重；参与者以 `operationNo + stepCode` 永久幂等。

## 7. HTTP 与安全

内部前缀：

```text
/api/v1/internal/account-lifecycle/wallet
```

接口：

- `POST /precheck`
- `POST /fence`
- `POST /actions`
- `GET /results/{operationNo}/{stepCode}`
- `POST /manual-resolutions`

所有接口只接受内部生命周期 Token。生产 profile 要求 Token 至少 32 字节且不能使用开发默认值。

## 8. 实施任务

1. 生成 P5 patch、回填 SQL、H2 schema 和结构契约测试。
2. 实现投影、事件去重、内部认证与启动校验。
3. 实现事务写门禁，并接入免密签约、默认协议、用户关闭及支付尝试创建。
4. 实现资金风险预检/最终检查、结构化 blocker。
5. 实现免密解约、渠道 `UNKNOWN`、参与者 Inbox 与永久结果查询。
6. 实现带审计的人工确认接口。
7. 增加低基数指标、结构化错误码和并发/回放/回滚测试。
8. 执行 `mvn -pl wallet verify` 及受影响链路模块验证。

## 9. 上线顺序

1. 人工执行 P5 patch。
2. 人工执行并核验 P5 backfill。
3. 部署 Wallet，保持 `SHADOW`。
4. P6 接通持续投影和真实参与者调度。
5. 覆盖率与影子指标稳定后再评估 `ENFORCE`。
