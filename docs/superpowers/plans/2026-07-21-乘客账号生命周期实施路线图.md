# 乘客账号生命周期实施路线图

> **路线图状态（2026-07-27）：** P1～P7 代码链路已经贯通；P1 数据库补丁已执行。
> 其余目标环境 patch/backfill 证据、真实 MySQL/Kafka 故障演练和生产逐级灰度尚未
> 全部完成。日常状态以 `docs/plans/乘客账号生命周期P1-P7执行计划索引.md` 为准。

> **面向智能体执行者：** 每个子项目必须先使用 `superpowers:writing-plans` 形成独立详细计划，再使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务实施；不得跨越验收门槛并行接管线上流量。

**目标：** 将已确认的换号/注销设计拆成七个可独立测试、观测和回滚的子项目，最终由 passenger 生命周期中心统一编排，而订单、钱包、券积分等领域只实现自己的参与者契约与写入门禁。

**架构：** passenger 内建立持久化编排 Saga，使用版本化 YAML 计划、Operation/Step 运行快照、不可覆盖 Event、Transactional Outbox 和参与者注册表；passenger-api 只负责认证与一致响应，各领域通过同步检查、幂等 Inbox、异步命令和状态查询参与流程。手机号始终只是可变登录凭据，资产归属稳定绑定 `customer.id`。

**技术栈：** Java 21、Spring Boot 3.3.5、MyBatis-Plus、MySQL 8/H2、Redis、Spring Kafka、OpenFeign/内部 HTTP、XXL-JOB 3.1.0、JUnit 5、Mockito、MockMvc。

## 全局约束

- 权威设计为 `docs/superpowers/specs/2026-07-20-乘客账号换号与注销统一生命周期_DESIGN.md`；发生冲突时先修订并重新确认设计，不在实现中自行改变口径。
- `customer.id` 永不因换号而改变；换号更新同一条 `customer.phone`，注销最终完成前不释放 `phone_active`。
- Operation 仅保存 `plan_code + plan_version + plan_digest`；实际运行快照在 `account_lifecycle_step` 及其 `step_config`，不增加 plan definition 表或 `plan_snapshot`。
- 注销在 `irreversible_started=0` 时才允许撤销；置为 1 后只允许前向重试或人工处理。
- 拦截器只做稳定动作码门禁，不执行清理、不发跨服务请求、不承担 Saga。
- 每个参与领域只判断和处理自己拥有的数据；中心不得复制订单、支付、券积分的判定 SQL。
- 每个异步参与者以 `operationNo + stepCode` 建立唯一 Inbox，Inbox 与领域副作用同事务提交。
- 内部调用超时、异常或 `UNKNOWN` 必须失败关闭；不得解释为无风险。
- 不可逆 Operation 不随应用回滚而回滚；版本回退只能停止新受理，恢复器必须继续处理已受理流程。
- 每个子项目必须执行 TDD，聚焦测试通过后再运行受影响模块 `verify`；Git 提交信息使用中文。

## 子项目依赖与交付顺序

```text
P1 生命周期内核
  -> P2 认证、OTP 与受限会话
      -> P3 动作门禁、影子预检与 order 参与者
          -> P4 calculate 参与者
          -> P5 wallet 参与者
              -> P6 编排执行、Kafka 恢复与人工处置
                  -> P7 线上切换与旧逻辑清理
```

P4 与 P5 在 P3 的参与者契约冻结后可以分别开发，但二者均不得在 P6 前接入真实注销执行。

### P1：生命周期数据、计划与本地状态机

**状态：已完成，Passenger 生命周期补丁已执行。**

**范围：** passenger 生命周期 DDL、H2 schema、YAML 计划加载/校验/摘要、运行快照实体与 Mapper、纯状态机、CAS 状态迁移、事务内 Operation/Step/Event/Outbox 持久化。

**明确不做：** 新 HTTP 接口、OTP、`auth_epoch` 生效、账户栅栏、Kafka 发布、参与服务调用、旧 settings 接管。

**验收门槛：** 应用对非法计划启动失败；创建的步骤不受后续配置对象修改影响；状态迁移受白名单和 row version 保护；一次事务失败时四类运行记录全部回滚；现有 settings 测试保持通过。

**详细计划：** `docs/superpowers/plans/2026-07-21-乘客账号生命周期基础设施.md`。

### P2：数据库认证代次、原子 OTP 与受限会话

**状态：已完成，并已被 P7 公开入口复用。**

**范围：** `customer.auth_epoch` 数据库权威、Redis 缓存投影、Purpose 隔离的 Lua 原子 OTP、普通/受限 token scope、换号与注销建栅栏事务、WS 撤销事件。

**入口契约：** 使用 P1 的计划注册表、运行快照工厂和事务持久化组件，不复制计划步骤。

**验收门槛：** OTP 并发只能成功一次；敏感事务失败时 customer/Operation/Event/Outbox 一起回滚；epoch 增加后旧 token 无法继续使用；受限 token 不能调用普通写接口。

**回滚边界：** 保留旧认证读取路径的配置开关，但数据库 epoch 已递增后不得恢复旧 token。

### P3：动作码门禁、影子预检与 order 参与者

**状态：已完成代码实现，生产启用前仍需执行回填覆盖率核验与真实 MySQL 8 并发验证。**

**范围：** 动作权限矩阵、passenger-api 快速拦截、order `AccountWriteFence`、生命周期投影、订单同步检查、结构化 blocker、参与者 Inbox/查询接口；新旧注销检查影子对比。

**入口契约：** `businessStatus + lifecycleStatus + tokenScope + actionCode`；order 只返回 `PASS/BLOCKED/UNKNOWN` 和稳定 blocker，不暴露内部 SQL。

**验收门槛：** `CANCELLING` 不能创建订单但能查询、取消和支付欠款；栅栏与并发下单竞态由领域写门禁加栅栏后复检关闭；影子差异有指标但不改变线上结果。

**回滚边界：** 可关闭影子流量和 BFF 快速拦截；领域高风险写门禁在 lifecycle 投影有效后不能无条件关闭。

**交付给 P4/P5 的冻结前置契约：** 参与者以 `operationNo + stepCode` 幂等，返回 `PASS/BLOCKED/UNKNOWN + blockers`；结构化 blocker 固定包含 `code/resourceType/resourceNo/action`；基础设施未知失败关闭；领域写门禁必须位于本领域事务边界内；Token、手机号、业务编号和异常 message 不得进入指标标签。

### P4：calculate 券积分参与者

**状态：代码和 P6 编排接入已完成；目标环境 patch/backfill 与投影覆盖率待留证。**

**范围：** 未结清计价/锁券检查、未使用券作废、积分清零或保留策略、`operationNo + stepCode` Inbox、结果事件和成功未知查询。

**验收门槛：** 重复命令不重复清券/清积分；换号不迁移也不清理资产；部分执行后回执丢失可由查询恢复；金额和积分流水保留审计链。

**回滚边界：** 参与者可以停止接受新命令，但已提交 Inbox 的结果必须继续可查询。

### P5：wallet 支付风险与免密解约参与者

**状态：代码和 P6 编排接入已完成；目标环境 patch/backfill、投影覆盖率及真实渠道
结果确认能力待生产验收。**

**范围：** 未结清支付/退款/争议检查、关闭免密、渠道成功未知查询、Inbox 与领域动作流水、人工处理边界。

**验收门槛：** 未结清资金义务始终阻断；重复命令不重复调用渠道；渠道超时不被判为成功；关闭免密未确认时不能最终注销；人工动作完整审计。

**回滚边界：** 渠道调用开关只能阻止新操作，已处于成功未知的步骤必须保留查询与人工处置能力。

### P6：编排执行、Outbox/Kafka、恢复与人工处置

**状态：代码实现、三个 XXL-JOB Handler 和本地注册配置检查已完成；真实
Kafka/服务宕机恢复演练与生产调度告警待验收。**

**范围：** participant registry、sequence 分组执行、不可逆闸门、Outbox 发布器、结果消费者、主动查询、指数退避、XXL 恢复、诊断查询和受控人工动作。

**验收门槛：** Kafka 不可用不丢命令；服务宕机可从数据库恢复；领域成功但回执丢失不会盲目重做副作用；REQUIRED 未完成不能 FINALIZE；POST_ACTION 不阻断核心安全完成但持续重试；所有人工动作写 Event。

**回滚边界：** 可关闭新受理和调度触发，不能删除或跳过 PENDING/PROCESSING/成功未知记录。

### P7：旧入口迁移、灰度切换与代码收束

**状态：代码侧已完成并保留五模块 558 个测试，乘客 H5 已迁移到新生命周期接口并通过生产构建；默认灰度 0%，等待部署环境验证、真实故障演练和生产逐级切流。Legacy Adapter 仅在 100% 稳定后删除。**

**范围：** 新生命周期 API、旧 settings 兼容转调、灰度比例、指标对比、操作查询体验、旧编排删除、运行手册和故障演练。

**验收门槛：** 换号与注销全部经统一 Application Service；代码扫描不存在业务模块自写注销清理分支；同手机号注销后可注册为新 `customer.id`；本地全链路测试通过；真实 MySQL/Kafka 故障演练在生产切流前完成；具备停止新受理与前向恢复手册。

**回滚边界：** 灰度期间可以把未受理流量切回旧入口；一旦新 Operation 已受理，必须由新流程查询、撤销或前向完成。

## 跨阶段质量门禁

每个子项目结束时都要保留以下证据：

- 本子项目聚焦测试命令和通过数量。
- 受影响模块 `mvn -pl <modules> -am verify` 结果。
- 数据库增量脚本与 H2 schema 字段一致性检查。
- `git diff --check` 和敏感字段扫描结果。
- 新增状态、动作码、事件类型和错误码的契约清单。
- 新增指标、告警、配置开关和回滚动作。
- 设计验收项到测试用例的可追踪映射。

只有当前子项目达到门槛并经评审，才为下一子项目编写精确到文件和测试命令的详细实施计划。
