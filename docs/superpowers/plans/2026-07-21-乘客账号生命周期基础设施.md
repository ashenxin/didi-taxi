# 乘客账号生命周期基础设施实施计划

> **面向智能体执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施本计划。每个行为严格遵循红灯—绿灯—重构，步骤使用复选框（`- [ ]`）跟踪。

**目标：** 在 passenger 模块建立不接管线上入口的账号生命周期内核，使版本化 YAML 能被严格校验并固化为 Operation/Step 快照，且 Operation 状态、审计 Event 与待发布 Outbox 能通过本地事务和 CAS 安全持久化。

**架构：** 新代码全部收束在 `com.sx.passenger.lifecycle`，分为 domain、plan、persistence、application 四层。plan 层只加载白名单 YAML 并生成确定性 SHA-256；domain 层提供无 Spring 依赖的状态机；persistence 层使用 MyBatis-Plus 映射已确认的六张表；application 层仅暴露供后续换号/注销用例组合的事务组件，不新增 Controller、不消费 OTP、不修改 customer 生命周期。Outbox 本期只可靠落库，不引入发布器。

**技术栈：** Java 21、Spring Boot 3.3.5、Jackson YAML、MyBatis-Plus 3.5.9、MySQL 8、H2 MySQL mode、JUnit 5、AssertJ、Mockito、Maven。

## 全局约束

- 权威设计为 `docs/superpowers/specs/2026-07-20-乘客账号换号与注销统一生命周期_DESIGN.md`，DDL 使用已评审的 `passenger_account_lifecycle_patch.sql`。
- 本期不修改 `AppCustomerSettingsController`、`AppCustomerSettingsService` 及其 DTO，不产生线上行为变化。
- 不增加 `account_lifecycle_plan_definition`、`account_lifecycle_plan_step_definition` 或 `plan_snapshot`；Operation 只保存 plan digest，Step 保存实际运行配置。
- YAML 文件随包发布、禁止热更新；已有版本不可覆盖，新流程必须新增版本文件。
- 配置中只允许枚举白名单，不允许脚本、SQL、Java 类名、外部 URL、密钥或敏感值。
- `account_lifecycle_event` 是不可覆盖审计流水，`account_lifecycle_outbox` 是可重试投递队列，二者不得合表或复用同一主键语义。
- JSON 列在 Java 实体中使用 `String`；本期不引入自定义 TypeHandler，以保持 MySQL JSON/H2 VARCHAR 一致。
- 所有状态迁移先经纯状态机校验，再以 `id + status + row_version` CAS 更新；更新数不是 1 时返回并发冲突。
- 本期创建运行快照不更新 `customer`，也不公开为业务 Service；后续 P2 顶层事务必须把 OTP、customer CAS/epoch、运行快照和 Outbox 组合在同一事务中。
- Git 提交信息使用中文，每个任务聚焦测试通过后独立提交；不得提交 `.superpowers/` 临时文件。

            LifecycleOperationType type,

            boolean irreversibleStarted);

    public void requireTransition(LifecycleStepStatus from, LifecycleStepStatus to);

**状态约束：**

- ACCOUNT_CANCEL 允许设计文档中的主路径、`FENCED/BLOCKED -> ABORTED`、重试和人工恢复；`irreversibleStarted=true` 时任何 `-> ABORTED` 都拒绝。
- PHONE_CHANGE 只允许 `REQUESTED -> EXECUTING -> COMPLETED`，以及 `EXECUTING <-> RETRY_PENDING/MANUAL_REVIEW` 的前向恢复；不允许进入 `FENCED/BLOCKED/ABORTED`。
- COMPLETED/ABORTED 为终态，不能迁出；同状态更新不视为状态迁移。
- Step 只允许从 PENDING 开始，终态 `SUCCEEDED/SKIPPED/CANCELLED` 不能迁出；BLOCKED 只能回 PENDING，RETRY_PENDING/MANUAL_REVIEW 只能回 RUNNING 或被取消。

**核心类型与接口：**

```java
public record ValidatedLifecyclePlan(
        String code,
        int version,
        LifecycleOperationType operationType,
        String digest,
        List<LifecycleStepDefinition> steps) {
    public ValidatedLifecyclePlan {
        steps = List.copyOf(steps);
    }
}

public interface LifecyclePlanRegistry {
    ValidatedLifecyclePlan activePlan(LifecycleOperationType operationType);
    ValidatedLifecyclePlan get(String code, int version);
}
```

Loader 使用 `ResourcePatternResolver` 读取 `classpath*:account-lifecycle/*.yml`；Configuration 在 bean 创建时一次性加载，运行期不可刷新。

**校验规则：**

- `schemaVersion == 1`；code 匹配 `[a-z][a-z0-9-]{2,63}`；version 大于 0；operationType 和 status 必须是白名单枚举。
- 同一 `code + version` 唯一，同一 operationType 只能有一个 ACTIVE 计划。
- step code 匹配 `[A-Z][A-Z0-9_]{2,63}` 且计划内唯一；participant、phase、executionMode、criticality 都必须映射到 Java 枚举。
- sequence 大于 0且不超过 100000；timeout 为 1..300 秒；`retry.maxAttempts` 为 0..20；initialIntervalSeconds 为 1..3600。schema v1 中 `maxAttempts` 固定解释为“首次调用之外的最大自动重试次数”，原值写入 `max_retry_count`，禁止实现时自行加减 1。
- ACCOUNT_CANCEL 必须且只能有一个 `ACCOUNT_FINALIZE_CANCEL`，其 phase/participant/mode/criticality 分别为 `FINALIZE/ACCOUNT/LOCAL_TRANSACTION/REQUIRED`，且 sequence 最大。
- PHONE_CHANGE 必须包含且只能包含一个 `IDENTITY_COMMIT_PHONE_CHANGE`；不得包含 ACCOUNT_CANCEL finalizer。
- 返回对象及 steps 必须防御性复制，注册后修改源 DTO 不得改变运行计划。

- Operation 状态更新受 status + rowVersion CAS 保护，并在同事务写不可覆盖 Event。

- `mvn -pl passenger verify` 与 `git diff --check` 有新鲜通过证据。
