# 乘客生命周期 P3 动作门禁与 Order 参与者实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立统一动作码门禁、Order 生命周期投影与不可绕过的领域写栅栏，并提供幂等的 Order 注销参与者及旧流程影子对比。

**Architecture:** Passenger 继续持有生命周期权威；passenger-api 依据每次认证回查得到的业务状态、生命周期状态和 token scope 执行动作矩阵；Order 保存版本化本地投影，在创建订单事务中锁定投影行做最终裁决。注销参与者使用同一投影行锁串行化 fence 与下单，并用 Inbox 保存稳定结果；P3 只提供同步命令，Kafka 恢复留给 P6。

**Tech Stack:** Java 21、Spring Boot 3.3.5、Spring MVC `PathPattern`、OpenFeign、MyBatis-Plus、MySQL 8、H2 MySQL mode、Micrometer、JUnit 5、Mockito、AssertJ。

## Global Constraints

- 用户确认 P3 采用直接执法：Order `RIDE_CREATE` 硬门禁不是影子模式，投影缺失或未知时失败关闭。
- Passenger 是 lifecycleStatus/lifecycleVersion 的唯一权威；Order 不生成或回退 lifecycleVersion。
- `lifecycle_version=0` 是合法初始版本。
- passenger-api 只做快速门禁；Order `AccountWriteFence` 是不可绕过的最终领域边界。
- CANCELLING + LIFECYCLE_RESTRICTED 允许订单查询、取消和支付欠款，禁止创建订单及其他新增义务。
- 旧 settings 的结果仍决定当前线上注销响应；P3 影子预检不得改变旧结果。
- Order lifecycle 内部接口使用独立 `ORDER_LIFECYCLE_INTERNAL_TOKEN`，不得复用 `PASSENGER_INTERNAL_TOKEN`。
- 指标 tag 只能使用固定 enum；禁止 customerId、operationNo、orderNo、手机号、Token 和异常 message。
- 不新增公开 lifecycle Controller，不接 calculate/wallet 执行动作，不实现 Kafka/XXL 恢复。
- 不运行 Docker/Testcontainers；H2 并发用例不能宣称完成真实 MySQL 行锁压测。
- P3.2、P3.3 完成后各进行一次高风险只读复审；其他任务采用主代理内联验证。

            .map(RouteRule::action)
            .findFirst();
}

- [ ] **Step 4: 实现失败关闭的权限矩阵**

```java
public PassengerActionDecision decide(Integer businessStatus, String lifecycleStatus,
                                      PassengerSessionScope scope, PassengerActionCode action) {
    if (businessStatus == null || businessStatus != 0) return DENY;
    if ("CANCELLED".equals(lifecycleStatus)) return DENY;
    if ("ACTIVE".equals(lifecycleStatus) && scope == NORMAL) return ALLOW;
    if ("CANCELLING".equals(lifecycleStatus) && scope == LIFECYCLE_RESTRICTED) {
        return RESTRICTED_ALLOWED.contains(action) ? ALLOW : DENY;
    }
    return knownLifecycle(lifecycleStatus) && scope != null ? DENY : UNKNOWN;
}
```

`RESTRICTED_ALLOWED` 固定为 `ORDER_READ/ORDER_CANCEL/DEBT_PAYMENT/PROFILE_READ/SESSION_LOGOUT/ACCOUNT_CANCEL`；P3 不把任何 URL 映射为 restricted `ACCOUNT_CANCEL`，直到后续阶段建立明确接口。

- [ ] **Step 4: 实现同步参与者服务**

```java
@Transactional
public OrderLifecycleParticipantResult fence(OrderLifecycleCommand command) {
    String hash = hasher.hash(command);
    OrderLifecycleParticipantInbox prior = inboxes.find(command.operationNo(), command.stepCode());
    if (prior != null) return replayOrConflict(prior, hash);

    projections.applyUnderLock(command.toProjectionCommand());
    BlockingOrderResult blocking = orderWriteService.findBlockingOrder(command.customerId());
    OrderLifecycleParticipantResult result = mapBlocking(blocking);
    requireOne(inboxes.insert(toInbox(command, hash, result)));
    return result;
}
```

`fence` 必须将投影推进为 CANCELLING，即使结果是 BLOCKED；这样用户只能取消订单或支付欠款，不能新增订单。`precheck` 只读，不改投影、不写 Inbox。

- [ ] **Step 5: 写两种并发顺序的失败测试**

使用两个线程和 latch 控制锁顺序：

1. create 先持有投影行锁并提交，fence 随后取得锁，必须返回 `BLOCKED/ACTIVE_ORDER`。
2. fence 先持有投影行锁并提交，create 随后取得锁，必须抛 `ACCOUNT_LIFECYCLE_BLOCKED`。

```sql
INSERT INTO `order`.`order_account_lifecycle_projection`
    (customer_id, business_status, lifecycle_status, lifecycle_version,
     operation_no, source_event_id, row_version, updated_at)
SELECT id, status, lifecycle_status, lifecycle_version,
       current_lifecycle_operation_no, CONCAT('P3-BACKFILL-', id, '-', lifecycle_version), 0, NOW()
FROM `passenger`.`customer`
WHERE is_deleted = 0
ON DUPLICATE KEY UPDATE
    business_status = IF(customer.lifecycle_version > order_account_lifecycle_projection.lifecycle_version,
                         customer.status, order_account_lifecycle_projection.business_status),
    lifecycle_status = IF(customer.lifecycle_version > order_account_lifecycle_projection.lifecycle_version,
                          customer.lifecycle_status, order_account_lifecycle_projection.lifecycle_status),
    operation_no = IF(customer.lifecycle_version > order_account_lifecycle_projection.lifecycle_version,
                      customer.current_lifecycle_operation_no, order_account_lifecycle_projection.operation_no),
    source_event_id = IF(customer.lifecycle_version > order_account_lifecycle_projection.lifecycle_version,
                         CONCAT('P3-BACKFILL-', customer.id, '-', customer.lifecycle_version),
                         order_account_lifecycle_projection.source_event_id),
    updated_at = IF(customer.lifecycle_version > order_account_lifecycle_projection.lifecycle_version,
                    NOW(), order_account_lifecycle_projection.updated_at),
    lifecycle_version = GREATEST(order_account_lifecycle_projection.lifecycle_version,
                                 customer.lifecycle_version);
```

赋值顺序必须保持 `lifecycle_version` 最后更新，前面的比较才能使用目标表更新前版本。文件末尾固定提供：

```sql
SELECT COUNT(*) FROM passenger.customer WHERE is_deleted = 0;
SELECT COUNT(*) FROM `order`.order_account_lifecycle_projection;
SELECT c.id FROM passenger.customer c
LEFT JOIN `order`.order_account_lifecycle_projection p ON p.customer_id = c.id
WHERE c.is_deleted = 0 AND p.customer_id IS NULL;
SELECT c.id, c.lifecycle_version, p.lifecycle_version
FROM passenger.customer c JOIN `order`.order_account_lifecycle_projection p ON p.customer_id = c.id
WHERE c.is_deleted = 0 AND p.lifecycle_version < c.lifecycle_version;
SELECT c.id, c.lifecycle_status, p.lifecycle_status
FROM passenger.customer c JOIN `order`.order_account_lifecycle_projection p ON p.customer_id = c.id
WHERE c.is_deleted = 0 AND c.lifecycle_version = p.lifecycle_version
  AND c.lifecycle_status <> p.lifecycle_status;
```

## 最终验收矩阵

| 场景 | 预期 |
|---|---|
| ACTIVE + NORMAL 创建订单 | BFF 与 Order 均允许 |
| CANCELLING + restricted 创建订单 | BFF 403；直连 Order 409 |
| CANCELLING 查询/取消/支付欠款 | BFF 允许，领域接口继续校验订单归属 |
| Order 投影缺失/未知 | 创建订单 503，失败关闭 |
| 旧版本/乱序投影 | 不覆盖新状态，记录 conflict/stale |
| 下单先获得投影锁 | 订单成功，注销参与者返回 BLOCKED |
| 注销先获得投影锁 | 投影 CANCELLING，下单 409 |
| 同 operationNo+stepCode+hash | 返回原参与者结果 |
| 同 key 不同 hash | 409，不改投影和 Inbox |
| 影子 precheck 超时/差异 | 只记 ERROR/差异指标，不改变旧 settings 结果 |
| 指标 Registry 异常 | 不影响门禁、事务和 HTTP 业务结果 |
| 内部 lifecycle Token 缺失/错误 | 401/403，不能执行参与者命令 |
