# 完单结算实施计划

> **面向智能体执行者：** 必须使用子技能：使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施本计划。步骤以复选框（`- [ ]`）语法跟踪。

**目标：** 实现司机完单后的异步最终计价、优惠券锁定、mock 免密/主动支付、结算查询和未结清订单拦截完整闭环。

**架构：** `order-service` 继续拥有订单和权威结算状态，并通过现有 Transactional Outbox 发布完单结算事件；同服务 Kafka 消费者幂等编排 `calculate-service` 与 `wallet-service`。`map-service` 和完单时长提供稳定、可复算且首次即冻结的本地 mock 输入。`wallet-service` 保存一单多次支付尝试并提供受环境限制的 mock 收银台；`passenger-api` 只做鉴权、聚合和页面入口，不决定金额或状态。

**技术栈：** Java 21、Spring Boot、Spring Kafka、OpenFeign、MyBatis-Plus、MySQL/H2、JUnit 5、Mockito、MockMvc

## 全局约束

- 全程执行 TDD：每个行为先写失败测试，再写最小实现，再运行聚焦测试。
- 金额统一使用 `BigDecimal`，先 `HALF_UP` 舍入两位再校验；严禁用 `max(..., ZERO)` 掩盖异常。
- `0.01 <= finalAmount <= 10000.00`、`0 <= discountAmount <= finalAmount`、`payableAmount = finalAmount - discountAmount`。
- 司机完单请求只使用可信登录司机 ID；客户端距离、时长、金额字段不得进入结算。
- 明确支付失败后不创建任何后台定时重扣任务；只有 `PAY_CONFIRMING` 查询原支付尝试。
- 优惠券在支付失败、取消和待确认期间保持 `LOCKED`，成功后才变为 `USED`。
- 本计划不实现司机/车队/运营公司的固定金额或比例分成；只保留现有 5% 平台服务费及承运侧收入字段。
- 不调用外部地图、支付宝、微信沙箱或生产 API。
- 文档同步任务会纳入 `乘客司机端_完单结算方案讨论.md`，保留其历史讨论价值，并以当前中文权威文档标明已确认、已落地状态。

- [x] **步骤 3： 实现确定性提供器并替换固定时间戳 traceId**

使用规范化起终点坐标与 `mock-route-v1` 做 SHA-256，映射到配置区间；同一输入不得使用 `Instant.now()` 或随机数。默认距离范围 `3000..30000` 米，时长由距离和确定性速度计算。`RouteController` 注入该提供器，`MapClient.drivingRoute` 改调 `/api/v1/map/route`。

```java
public RouteResponse route(RouteRequest request) {
    String seed = version + '|' + canonical(request);
    long hash = unsignedLong(sha256(seed));
    long distance = minDistanceMeters + hash % (maxDistanceMeters - minDistanceMeters + 1);
    long duration = Math.max(60, Math.round(distance / deterministicMetersPerSecond(hash)));
    return new RouteResponse(distance, duration, "LOCAL_MOCK_ROUTE", version, shortHash(seed));
}
```
