A · BFF 同步责任链
H5 → passenger-api
订单检查 → 结算检查 → 钱包检查 → 券/积分清理 → 删除账号

最小重构

把现有 if/Feign 调用改为 AccountGuard 链和策略列表。

优势

  • 改动小、上线快
  • 能先拆小大方法

局限

  • 崩溃后无法恢复
  • 成功未知与重复副作用
  • BFF 继续成为业务权威
B · 乘客域持久化编排 Saga（推荐）
H5 → BFF → Account Lifecycle
状态机 + Operation/Step + Outbox
Order ｜ Wallet ｜ Calculate ｜ Session/WS ｜ Future Domains
回执 · 重试 · 对账 · 人工处理

统一控制面，领域自治

passenger 拥有生命周期状态和进度，各业务只实现标准参与者契约。

优势

  • 可查询、可重试、可审计
  • 新增业务只注册参与者
  • 复用现有 Outbox/Kafka/XXL

成本

  • 需增加状态表与事件契约
  • 参与者必须真正幂等
C · 纯 Kafka 事件编舞
passenger 发布 AccountCancellationRequested
↙ Order　↓ Wallet　↘ Calculate　→ Future
各服务独立消费和清理

低耦合扇出

各服务自由订阅事件，中心不直接编排步骤。

优势

  • 参与服务耦合较低
  • 扇出扩展容易

局限

  • 没有统一完成判定
  • 失败定位与合规证明困难
  • 补偿链条复杂

推荐组合的职责切面

Filter / Interceptor：身份、生命周期状态门禁、Request-ID、审计上下文
责任链：只读资格校验，返回结构化 blockers
策略注册表：按 CHANGE_PHONE / CANCEL_ACCOUNT 解析参与步骤
Saga：状态推进、幂等、超时、重试、死信、人工处理
各领域：保留自己的订单、支付、券、积分与流水裁决权
