# 车队营销优惠券 PRD

> 本文档由《车队营销优惠券规则_讨论稿.md》拆分而来，描述一期车队营销优惠券的产品范围、业务口径、权限边界与验收口径。
> 技术方案见《车队营销优惠券_TECH.md》，接口契约见《车队营销优惠券_API.md》，SQL 草案见《车队营销优惠券_SQL.md》。

## 1. 背景

优惠券最初出现在乘客端「我的钱包」中，但其本质不只是用户资产展示，而是会影响订单车费、乘客实付、平台服务费、车队收入、退款和对账。

因此一期将优惠券定义为：

```text
车队可配置、由 calculate 侧执行计算的营销计价规则。
```

钱包只负责展示乘客已经持有的券；优惠券模板、领取、可用性判断、优惠金额计算、锁定和核销属于计价营销能力。

## 2. 产品目标

- 支持车队级优惠券模板配置。
- 支持乘客登录时领取当前可领取优惠券。
- 支持订单结算时自动选择最优优惠券。
- 支持用户选择不使用优惠券。
- 支持优惠券锁定、释放、核销和金额留痕。
- 支持平台服务费按优惠后乘客实付车费计算。
- 后台可从计价规则详情页查看同范围优惠券方案。

## 3. 一期范围

### 3.1 支持的券类型

| 类型 | 示例 | 一期支持方式 |
|---|---|---|
| 固定金额减免 | 满 35 减 5；无门槛减 3 | `AMOUNT_OFF` |
| 比例折扣 | 满 35 打 9 折；全单 8 折 | `PERCENT_OFF` |
| 封顶折扣 | 打 8 折，最多减 20 | `PERCENT_OFF + max_discount_amount` |
| 日期/节日/限时 | 国庆 10 月 1 日到 10 月 7 日 | 固定 `valid_start_at / valid_end_at` |
| 适用范围 | 仅杭州快车可用 | `city_code + product_code` |

### 3.2 特殊活动预留

以下活动本期不做后台通用配置，但预留 `activity_code` 和 `rule_config`：

- banner 点击领取券
- 广告活动券
- 分享活动券
- 首单券
- 会员等级券
- 指定人群券
- 机场/火车站券
- 指定路线券

特殊活动必须经过运营参与，并与车队线下达成一致。活动入口后续可以通过 banner、活动页、配置文件、Redis 或发版方式承接，但用户持券、用券、结算必须落表。

## 4. 不做范围

- 不做平台券。
- 不做多券叠加，后续也不扩展券叠加。
- 不做系统内发布商讨流程。
- 不记录运营确认人、车队确认人、确认时间、确认凭证。
- 不做模板导出。
- 不做复制模板。
- 不做最大优惠金额、最低折扣率、同一时间启用数量等复杂风控阈值。
- 不做部分退款。
- 不拆司机最终收入、车队收费、司机净收入。
- 不新增 `fleet_id`。
- 不在 `fare_rule` 表新增优惠券字段。

## 5. 归属与责任

### 5.1 车队归属

当前系统中 `capacity.company.id` 表示“公司 + 车队”的承运单元，产品上可称为车队，技术上统一使用 `company_id`。

```text
coupon_template.company_id = 发券车队
driver.company_id = 司机所属车队
trip_order.company_id = 订单最终承运车队
fare_rule.company_id = 基础计价规则所属车队
```

本期不引入 `fleet_id`。

### 5.2 优惠券归属

优惠券模板归属车队，用户领取后优惠券实例归属乘客。

```text
模板归属：company_id
用户券归属：passenger_id / user_id
手机号：不参与归属判断
```

用户更换手机号后，优惠券不能丢失。

### 5.3 成本与责任

- 不存在平台券。
- 优惠成本与经营责任全部由发券车队承担。
- 运营只能提出活动建议和协助系统发布，不能绕过车队单方面发券。
- 是否发布、发布什么内容，由运营所在公司与车队在线下会议或邮件中沟通清楚。
- 系统只记录模板状态，不承载协商过程。

## 6. 后台权限

### 6.1 可见范围

优惠券可见范围复用计价规则可见范围：

```text
登录者能看到某条计价规则，就能从该计价规则详情页查看同范围优惠券方案。
```

同范围指：

```text
company_id + city_code + product_code
```

### 6.2 操作权限

| 角色 | 权限 |
|---|---|
| 超管 | 创建、编辑、发布、下架、查看统计 |
| 非超管 | 只读查看 |
| 车队账号 | 只读查看自己可见范围内优惠券 |

如果车队发现模板配置错误，需要向运营反馈，由运营与车队重新确认后，再由超管调整。

### 6.3 状态流

```text
DRAFT 草稿
  -> PUBLISHED 已发布
  -> OFFLINE 已下架
```

只有 `PUBLISHED` 且在有效期内、未领完的优惠券模板，才可出现在乘客登录领取弹窗。

## 7. 领取规则

- 用户每次登录时，系统搜索该用户当前可领取的所有优惠券。
- 如果存在可领取券，前端弹框询问是否领取全部。
- 用户确认后，一次性领取全部当前可领取券。
- 用户取消则本次不领取，下次登录仍可再次提示仍符合条件的券。
- 已领完的券不展示。
- 当前用户已领取过的券不展示。
- 本期不建正式领取流水表，最多写业务日志。

领取限制：

```text
total_count：模板总发放上限，必须设置
per_user_limit：每人限领数量，默认 1
```

## 8. 使用规则

- 一笔订单最多使用一张优惠券。
- 系统默认自动选择最优券。
- 用户可手动选择不使用优惠券。
- 不支持多券叠加。
- 不满足车队、城市、产品线、时间、金额门槛的券不可用。

最优券规则：

```text
1. 计算每张可用券在本单上的实际优惠金额。
2. 优惠金额最大者优先。
3. 优惠金额相同，valid_end_at 更早者优先。
4. 仍相同，user_coupon.id 更小者优先。
```

折扣券和封顶折扣券必须结合订单金额动态计算实际优惠金额。

## 9. 异步派单资金风险

当前两段式异步派单可能出现：

```text
下单预估阶段使用 A 车队 company_id
最终异步派单接单司机属于 B 车队 company_id
```

优惠券进入结算后，该问题涉及真实金额，不能只作为展示误差。

一期口径：

- 预估价可基于候选司机 `company_id` 展示预计金额。
- 支付前确认价必须基于最终承运司机/订单 `company_id` 重新计算。
- 优惠券锁定和核销必须基于最终 `trip_order.company_id` 校验。
- 完单结算必须基于最终 `company_id`、最终金额、优惠券快照和结算快照。
- 最终司机未确定前，不锁定强车队绑定优惠券，只能展示预计可用。

## 10. 金额口径

一期确认：

```text
优惠前车费 = trip_order.final_amount
优惠金额 = coupon_discount_amount
乘客实付车费 = payable_amount = final_amount - coupon_discount_amount
平台服务费 = payable_amount * 5%
承运侧收入 = payable_amount - 平台服务费
```

说明：

- 平台服务费按乘客优惠后实付车费计算。
- 不按司机到手金额计算。
- 不按承运侧收入反推计算。
- 优惠成本由发券车队承担。
- 本期只计算到承运侧收入，不拆司机最终收入和车队收费。

## 11. 退款与退券

- 支付失败：立即释放已锁定优惠券。
- 全额退款：退乘客实付金额，券恢复为 `UNUSED`；如果退款发生时券已过期，则置为 `EXPIRED`。
- 部分退款：一期不支持。

## 12. 验收口径

- 后台能从计价规则详情页查看同范围优惠券方案。
- 超管能创建、编辑、发布、下架优惠券模板。
- 非超管只能查看，不能增删改或启停。
- 登录时只展示当前用户可领取、未领完、未领取过的券。
- 用户确认后能一次领取全部可领取券。
- 用户换手机号后，已领取券仍存在。
- 订单只能使用一张券。
- 系统能自动选择实际优惠最大的券。
- 用户可选择不使用券。
- 用券动作必须有锁定、释放、核销等留痕。
- 结算快照保存优惠金额、乘客实付、平台服务费、承运侧收入。
- 不修改 `fare_rule` 表结构。
