# 乘客端个人中心「设置」二期 PRD

> 本文档描述乘客端个人中心新增「设置」功能的产品口径、风险点与处理方案。
> 「设置」与「我的订单」同属于个人中心下的二期功能，二者为平级入口。

---

## 1. 背景与目标

- 乘客在个人中心需要管理账号安全相关操作。
- 本期新增「设置」入口，包含两个子功能：
  - `更换手机号`
  - `注销账号`
- 本期重点是账号身份安全、历史打车记录保留、注销后的数据留存边界。

---

## 2. 功能层级

- 一级入口：个人中心
- 二级入口：
  - `我的订单`
  - `设置`
- 「设置」页面内包含：
  - `更换手机号`
  - `注销账号`

---

## 3. 本期交付范围

### 3.1 更换手机号

- 已登录乘客可进入「设置」发起更换手机号。
- 更换手机号必须校验当前登录态，并由服务端根据 token 中的用户 ID 查询当前绑定手机号。
- 更换手机号必须验证新手机号验证码。
- 新手机号不能属于任何未注销账号。
- 不支持账号合并。
- 更换成功后，当前登录态立即失效，乘客需要使用新手机号重新登录。
- 更换手机号后，原账号的历史订单、昵称、头像、实名等用户信息继续保留。

### 3.2 注销账号

- 已登录乘客可进入「设置」发起注销账号。
- 注销前必须校验当前账号没有进行中订单。
- 注销账号需要当前绑定手机号短信验证码，并进行二次确认。
- 注销采用逻辑删除，不做物理删除。
- 注销成功后，当前登录态立即失效，乘客回到登录页。
- 注销后后台继续保留并可展示历史订单、账号记录等运营数据。
- 注销后手机号允许重新注册，新注册账号为新的用户 ID，不继承旧账号订单。

---

## 4. 本期不做

- 不做账号合并。
- 不做旧手机号不可用时的客服申诉换绑流程。
- 不做注销后的物理删除。
- 不做历史订单迁移。
- 不做注销账号恢复。
- 不做多端设备管理页面。
- 不做复杂实名/人脸验证。

---

## 5. 核心产品口径

### 5.1 用户身份口径

- 系统内乘客身份以 `customer.id` 为准。
- 手机号是登录标识和可变账号字段，不是订单归属主键。
- 更换手机号时，只更新当前 `customer.id` 对应记录的手机号。
- 历史订单继续通过原 `customer.id` 归属到同一乘客账号。

### 5.2 更换手机号口径

- 当前登录态用于证明操作者已登录当前账号。
- 服务端根据 token 中的 `customer.id` 查询当前绑定手机号，不信任前端传入的旧手机号。
- 新手机号验证码用于证明操作者控制新手机号。
- 验证码需使用独立业务 key，不复用登录验证码 key。
- 新手机号验证码发送前需校验该手机号未被其他未注销账号占用。
- 更换成功后不自动续登，必须重新登录。

### 5.3 注销账号口径

- 注销账号前必须没有进行中订单。
- 进行中订单包含所有未完成、未取消的订单状态。
- 如存在进行中订单，禁止注销，并提示用户先完成或取消当前订单。
- 注销账号采用 `is_deleted=1` 的逻辑删除方式。
- 注销成功后旧 token 立即失效。

### 5.4 注销后重新注册口径

- 注销后同一手机号允许再次注册。
- 重新注册会创建新的 `customer.id`。
- 新账号不继承旧账号订单、实名、头像、昵称等信息。
- 旧账号历史订单继续保留在后台，仍关联旧 `customer.id`。

---

## 6. 风险点与处理方案

### 6.1 更换手机号后历史记录丢失风险

**风险描述**

如果更换手机号时错误地创建新账号，历史订单仍关联旧 `customer.id`，用户会看不到原打车记录。

**处理方案**

- 更换手机号必须更新同一条 `customer` 记录。
- 禁止通过新手机号创建新 `customer.id` 来完成换绑。
- 订单、个人资料、实名信息继续挂在原 `customer.id` 下。
- 当前绑定手机号以服务端按 `customer.id` 查询结果为准。

**验收关注**

- 更换手机号前后，用户 ID 不变。
- 重新登录后仍能查看原「我的订单」记录。

### 6.2 新手机号已存在风险

**风险描述**

如果新手机号已绑定另一个未注销账号，直接换绑会造成账号冲突或隐性合并。

**处理方案**

- 新手机号发送验证码前先校验是否已被未注销账号占用。
- 更换提交时再次校验，防止并发抢占。
- 若已占用，提示“该手机号已被使用”。
- 本期不支持合并账号。

### 6.3 仅依赖登录态更换手机号的安全风险

**风险描述**

更换手机号不验证旧手机号验证码后，若用户 token 被盗，攻击者可能在控制新手机号验证码的情况下完成换绑。

**处理方案**

- 接受该风险，以降低二期使用和开发复杂度。
- 更换手机号必须校验合法登录态，且 token version 必须有效。
- 新手机号必须通过独立验证码验证。
- 新手机号不得属于任何未注销账号。
- 更换成功后立即递增 token version，使旧 token 失效。
- 页面文案提示“更换成功后需重新登录”。

### 6.4 验证码业务混用风险

**风险描述**

若更换手机号、注销账号复用登录验证码 key，可能出现验证码串用，后续业务也难以维护。

**处理方案**

- 更换手机号的新手机号验证码使用独立验证码 key。
- 注销账号使用独立验证码 key。
- 按业务场景区分发送频控、验证码校验和日志。

### 6.5 更换手机号后旧 token 继续可用风险

**风险描述**

更换手机号属于敏感操作，旧 token 若继续有效，会导致旧登录态仍可操作账号。

**处理方案**

- 更换成功后递增 token version。
- 前端清除本地 token 和用户信息。
- 跳转登录页，用户使用新手机号重新登录。

### 6.6 注销时仍有进行中订单风险

**风险描述**

用户若在有进行中订单时注销，可能导致订单履约、司机通知、客服处理出现断链。

**处理方案**

- 注销提交前查询当前用户全部非终态订单。
- 有进行中订单时拒绝注销。
- 不在注销流程中自动取消订单，避免误取消和责任不清。

### 6.7 注销后后台数据展示风险

**风险描述**

注销后后台继续展示历史数据，但手机号未来可能被重新注册，按手机号查询时可能出现旧账号和新账号混淆。

**处理方案**

- 后台数据展示以 `customer.id` / `passenger_id` 作为强标识。
- 手机号仅作为搜索条件或展示字段。
- 后台应展示账号状态，区分正常账号与已注销账号。
- 订单仍按原 `passenger_id` 关联旧账号，不迁移到新账号。

### 6.8 注销后手机号重新注册风险

**风险描述**

同一手机号重新注册后，会形成“同手机号多个历史账号”的情况。

**处理方案**

- 接受该风险，以降低二期开发复杂度。
- 新注册账号生成新的 `customer.id`。
- 用户端只展示当前登录账号的数据。
- 后台保留旧账号记录并标识已注销。

### 6.9 逻辑删除带来的隐私风险

**风险描述**

逻辑删除会继续保留手机号、实名、订单等历史数据。

**处理方案**

- 本期以业务留痕、订单追溯、后台运营为优先。
- 用户端视角下账号不可再登录、不可再查看旧数据。
- 后续如有更高隐私要求，再评估脱敏归档或字段擦除策略。

### 6.10 并发操作风险

**风险描述**

用户可能在注销或换绑同时发起下单、登录、刷新订单等操作。

**处理方案**

- 更换手机号和注销成功后立即递增 token version。
- 依赖现有 JWT token version 校验使旧请求失效。
- 注销提交时再次校验订单状态与账号状态。
- 后续实现可在下单入口补充账号未注销校验。

## 7. 页面流程

### 7.1 设置首页

- 展示当前账号手机号，做中间四位脱敏。
- 展示两个入口：
  - `更换手机号`
  - `注销账号`

### 7.2 更换手机号流程

1. 用户进入「设置」。
2. 点击「更换手机号」。
3. 页面展示当前绑定手机号脱敏信息。
4. 用户输入新手机号。
5. 用户获取并输入新手机号验证码。
6. 用户提交。
7. 服务端根据 token 中的 `customer.id` 查询当前账号与当前绑定手机号。
8. 服务端校验登录态、新手机号、验证码、手机号占用状态。
9. 更换成功后提示“手机号已更换，请重新登录”。
10. 前端清除登录态并跳转登录页。

### 7.3 注销账号流程

1. 用户进入「设置」。
2. 点击「注销账号」。
3. 页面展示注销影响说明。
4. 用户获取并输入当前绑定手机号验证码。
5. 用户阅读二次确认文案并确认注销。
6. 服务端校验验证码和进行中订单。
7. 若存在进行中订单，提示用户先完成或取消订单。
8. 若允许注销，服务端逻辑删除账号。
9. 注销成功后提示“账号已注销”。
10. 前端清除登录态并跳转登录页。

## 8. 文案建议

### 8.1 更换手机号说明

- “更换后将使用新手机号登录，当前登录状态会失效。”
- “更换手机号不会影响您的历史订单和账号资料。”
- “新手机号不能是已注册账号。”
- “当前手机号由系统自动校验，无需输入原手机号验证码。”

### 8.2 注销账号说明

- “注销后，您将无法继续使用当前账号登录。”
- “注销后，用户端不再展示该账号的历史订单。”
- “为保障交易、客服和审计需要，平台后台会继续保留历史订单记录。”
- “注销后，该手机号可重新注册为新账号，但不会继承原账号订单。”
- “若当前存在进行中订单，请先完成或取消订单后再注销。”

---

## 9. 验收标准

- 个人中心可看到与「我的订单」平级的「设置」入口。
- 设置页可进入「更换手机号」和「注销账号」。
- 更换手机号必须校验当前登录态，并验证新手机号验证码。
- 新手机号已被未注销账号占用时，不允许更换。
- 更换手机号成功后，当前用户 ID 不变，历史订单保留。
- 更换手机号成功后，当前登录态失效，需要重新登录。
- 注销账号时，如果存在进行中订单，不允许注销。
- 注销账号成功后，账号逻辑删除，当前登录态失效。
- 注销后后台可继续查询历史订单。
- 注销后同手机号可重新注册为新账号，新账号不继承旧订单。
