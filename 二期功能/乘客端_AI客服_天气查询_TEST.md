# 乘客端 AI 客服：天气查询 skill TEST

> 2026-10-25。天气 skill 第一版代码完成。本文记录验收口径和当前自动化结果；真实高德 Key、配额和页面联调仍需在运行环境完成。

## 1. 验收范围

- 已实现：单城市/区县、今天到后天/大后天、文本回答、缺城市追问、日期越界说明、城市不存在说明、上游失败稳定错误码。
- 不在本期：沿途天气、天气预警、空气质量、多城市对比、按 GPS 或路线自动推断城市、天气对 ETA/路况的影响。
- 天气轮次不修改当前路线、`routeRef`、路线卡片或核查上下文。

## 2. 核心验收

- “杭州明天天气”返回杭州明天预报；正文包含城市、日期、星期、白天/夜间天气、气温、风向风力；有雨时追加带伞提示。风向/风力必须带单位，例如“东北风 1-3级”，不得显示成“东北1-3”。
- “明天会下雨吗”在没有可复用天气上下文时返回“请告诉我城市和日期，例如：杭州明天天气。”，不调用高德，不猜 GPS 或路线城市；上一轮是同会话天气回答时，复用其城市并在正文前说明“按你刚才说的杭州查：”。
- “杭州天气怎么样”按今天查询。
- “杭州下周六天气”返回“目前只能查今天、明天、后天、大后天这四天的预报”，不调用高德。
- “不存在市今天天气”返回“没有找到……请补充省份或换一个名称”，不返回 `turn.failed`。
- 高德超时、无权限、限流或返回 `status!=1` 时返回 `turn.failed`，错误码 `AI_WEATHER_UNAVAILABLE`，文案为“天气服务暂时不可用，请稍后重试”。
- 天气成功轮次的 `answer.completed.payload.weather` 包含地点、日期、星期、天气、温度和归一化后的风向/风力；不包含坐标、POI、密钥或路线数据。
- 天气追问只复用同一会话上一轮已持久化天气回答的城市；显式城市覆盖复用；不跨会话、不使用 GPS、地图页或当前路线城市。
- “后天会下雨吗”被追问城市后，只回“德清”时用德清和后天继续天气，不再追问起终点；问城市消息的服务端 `weatherContext` 不出现在公开 SSE、历史或请求状态中。
- “从 A 到 B，这条路线经过 X 吗”仍按路线核查处理，不进入天气 skill。
- 天气查询前后，当前路线和已有路线卡片不发生变化。

## 4. 运行环境与端到端验收

- 在 Nacos 的 `map-service-local.yml` 确认 `map.amap.key`（或环境变量 `AMAP_KEY` / `MAP_AMAP_KEY`）有效，并在高德控制台确认该 Key 已开通 Web 服务 API 的天气查询权限。
- 重启 `map-service`（8094）和 `passenger-api`（8100），保持 gateway、passenger-service、Nacos、MySQL、Redis 运行。
- 在乘客 H5 已登录会话直接发送：
  - “杭州明天天气”
  - “后天呢”（紧接上一轮，确认复用杭州并出现“按你刚才说的杭州查：”）
  - “后天会下雨吗” → “德清”（确认用德清和后天继续天气，不再追问起终点）
  - “上海明天天气”（确认显式城市覆盖，不出现“按你刚才说的”前缀）
  - 新会话里“明天会下雨吗”（确认没有天气上下文时追问城市）
  - “杭州下周六天气”
  - “不存在市今天天气”
- 核对 SSE 事件顺序：`turn.started` → `answer.completed` → `turn.completed`；上游失败时为 `turn.failed`。
- 核对天气轮次后继续问“这条路线经过五常收费站吗”，确认仍按当前路线核查，路线卡未被天气轮次改写。
- 记录高德真实返回的城市名、日期和温度，作为页面验收样本。

## 5. 待观察
