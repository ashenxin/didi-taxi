# 乘客端「福利签到」PRD

> 记录日期：2026-07-14
> 范围：乘客端福利页「立即签到」、28 天月度签到、积分展示、账号注销/换号边界。
> 状态：产品口径已基本定版，待 API/TECH 联调细化。

---

## 1. 背景

乘客端「每月签到领积分」后端能力已经落地：支持月度签到概览、积分查询、每日幂等签到，以及账号注销时清理积分。本文保留产品口径，并为后续任务中心、积分商城、优惠券兑换预留基础。

本期不做复杂任务中心，不做积分兑换，不做积分过期。

---

## 2. 产品目标

1. 乘客每天可在福利页完成一次签到。
2. 签到后获得积分，积分由后端计算，前端不传积分数。
3. 签到页展示每月 28 天进度。
4. 每月 1 号刷新新一轮签到。
5. 连续签到第 7 天给连续奖励。
6. 乘客可刷新查看当前积分总和。
7. 注销账号后积分余额清零；更换手机号保留积分。

---

## 3. 功能范围

### 3.1 月度 28 天签到

规则：

```text
自然月 1-28 号开放签到。
每月 28 号视为本月签到最后一天。
自然月 29-31 号不开放签到，也不能补签当月。
下个月 1 号刷新新一轮 28 天签到页。
```

页面状态：

- 1-28 号：可展示今日签到按钮。
- 已签到：展示「今日已签到」。
- 29-31 号：展示“本月签到已结束，下月 1 号刷新”。

### 3.2 签到奖励

奖励规则：

| 连续天数 | 当天奖励 |
| --- | --- |
| 第 1 天 | 5 积分 |
| 第 2 天 | 5 积分 |
| 第 3 天 | 5 积分 |
| 第 4 天 | 5 积分 |
| 第 5 天 | 5 积分 |
| 第 6 天 | 5 积分 |
| 第 7 天 | 35 积分 |
| 第 14 天 | 35 积分 |
| 第 21 天 | 35 积分 |
| 第 28 天 | 35 积分 |

说明：

- 连续第 7 天的 35 积分是当天总奖励，不叠加普通 5 积分。
- 连续天数每月 1 号清零，不跨月计算。
- 配置变更后，历史签到奖励不重算。

### 3.3 积分展示

福利页展示乘客当前可用积分：

- 页面进入时加载积分。
- 点击刷新按钮可重新查询积分。
- 点击签到成功后刷新积分总和。
- 首次查询积分时，如果积分账户不存在，返回 0。

### 3.4 异常状态

| 场景 | 前端表现 |
| --- | --- |
| 今日已签到 | 展示「今日已签到」 |
| 29-31 号进入 | 展示“本月签到已结束，下月 1 号刷新” |
| 配置文件缺失或非法 | 展示“签到配置异常，请稍后再试” |
| 账号已注销/注销中 | 不允许签到 |

## 4. 账号边界

### 4.1 注销账号

注销账号后：

- 积分余额清零。
- 不物理删除签到记录、积分账户记录、积分流水记录。
- 写入一条注销清零积分流水。
- 该 `customerId` 后续禁止签到和积分入账。

### 4.2 注销后重新注册

同手机号重新注册：

- 生成新的 `customerId`。
- 新账号积分从 0 开始。
- 旧账号积分不继承。

### 4.3 更换手机号

更换手机号：

- `customerId` 不变。
- 积分跟 `customerId` 走。
- 签到记录、积分流水、积分余额继续保留。
- 换号当天如果已签到，换号后不能再次签到。

---

## 5. 本期不做

- 不做积分兑换。
- 不做积分过期。
- 不做补签。
- 不做跨月连续签到。
- 不做完整规则引擎。
- 不做分区、分库分表。
- 异常补偿任务已经实施，范围见《乘客端_福利签到_异常补偿_TECH.md》。

## 6. 后续演进

- 奖励规则可从简单 YAML 配置演进为条件奖励配置。
- 后续积分商城再设计冻结、扣减、退款返还等流水。
- 表数据量变大后，再评估归档、分区或拆分。
- 福利签到异常补偿按 MySQL 权威重建 Redis Bitmap；MySQL 积分异常只检测和留痕，不自动修改积分。
- 异常明细只写入 `benefit_reconciliation_issue`；任务批次使用 XXL-Job 日志，不单独建表。
- 更换手机号后 `customerId` 不变，签到和积分不迁移；注销后清零调用完全丢失的跨服务边界本期只记录调用错误，不自动改积分。
