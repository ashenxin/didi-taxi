二期按业务范围划分，不按代码提交时间划分。服务于二期业务的后续修复、补偿、并发治理和运行脚本仍归对应二期功能。

## 二期核心边界

### 乘客账号与个人中心

- `passenger` 是乘客生命周期状态、版本和 `auth_epoch` 的权威来源；手机号是可变登录凭据，换号不改变 `customer.id`。
- 换号和注销提交必须遵守幂等与乐观版本约束；注销受理不等于注销完成，最终状态以 operation 查询结果为准。
- 旧 settings 入口仅用于灰度回退；当前阶段、恢复方式和下线条件以[执行计划索引](../docs/plans/乘客账号生命周期P1-P7执行计划索引.md)及[运行手册](../docs/runbooks/乘客账号生命周期P7灰度切换与前向恢复手册.md)为准。

### 钱包、优惠券与结算

- 乘客端只通过 `passenger-api` 访问钱包、优惠券和结算能力，不直连核心服务。
- `wallet` 负责免密协议和支付单；`calculate` 负责优惠券、签到和积分；`order` 负责订单结算快照。
- 结算、优惠和支付字段写入 `trip_order_settlement`，不继续膨胀 `trip_order`。
- 优惠券匹配和结算必须以最终承运司机对应的 `trip_order.company_id` 为准，不能使用预估阶段候选司机的公司信息。
- 真实支付、退款、对账、平台服务费和承运侧收入属于资金安全范围，必须以定版文档和财务评审结论为准。

### 福利签到与积分

- MySQL 签到记录、积分账户和积分流水是权威数据；Redis Bitmap 只记录签到事实并辅助统计。
- 异常补偿可以修复或重建 Bitmap；MySQL 三表差异只记录到 `benefit_reconciliation_issue`，不得自动修改积分。
- 当前功能范围是签到、积分查询和注销清零，不包含积分兑换、积分过期或复杂分库分表。

### 司机换队、行程与看板

- 换队申请、司机归属和接单资格以 `capacity` 的权威状态为准；申请处理中不得绕过资格校验接单。
- 行程记录从成功接单开始。拒单和确认超时不生成记录；成功接单后的取消与改派按每次司机服务分别留痕。
- 今日运营按 `Asia/Shanghai` 自然日统计，只使用符合口径的最终订单金额，不将其表述为司机净收入。
- 行程记录建表脚本归 `order` 模块；历史回填必须在暂停订单写流量、完成备份并核对多司机、终态和金额隔离后执行。

### 车队营销优惠券

- 优惠券属于 `calculate` 的计价营销能力，不放入 `wallet` 库，也不向 `fare_rule` 增加优惠券字段。
- 方案按 `company_id + city_code + product_code` 与计价规则并行匹配；现阶段 `company_id` 表示公司/车队/承运单元。
- 一笔订单最多使用一张券；锁定、释放、核销、退款恢复和过期等金额动作必须留痕。
- 手机号领取过同一模板后，注销再注册不能重复领取；风控身份只保存手机号哈希，不保存明文手机号。
- 正式产品和技术口径以 PRD、TECH、API、SQL 为准，[讨论稿](车队营销优惠券规则_讨论稿.md)只用于追溯决策来源。

### AI 客服

- 当前范围只覆盖下单前的单个指定途经点路线预览，不直接创建或修改订单，不展示预估车费。
- 地图结果来自高德真实地图能力；大模型负责意图理解和歧义追问，不能编造 POI 或路线。
- 项目已引入 Spring AI、Spring AI Alibaba 和 DashScope 相关依赖；密钥只能通过运行环境注入，不得写入仓库。
- `map` 已完成受控 POI 查询、WGS84 转高德坐标、单途经点路线、参考路线差值、折线解析和 Spring AI Tool 边界，并有对应单元测试。
- 当前尚未完成 Agent 对话编排、乘客 BFF 接口、会话持久化定版和前端真实地图/对话数据联调；乘客端页面仍是静态交互演示。
- 当前开发入口和已确认决议以 [AI 客服 PRD](乘客端_AI客服_指定途经点路线规划_PRD.md)为准。

## 上线与数据准备

- 二期复用根 README 中的 Nacos、MySQL、Redis、Kafka 和 XXL-JOB 环境；专项配置以相应 TECH 和运行手册为准。
- 数据库脚本的归属和执行顺序统一从 [SQL 说明](../docs/sql/README.md)进入，不复制脚本到二期目录制造第二份权威来源。
- 生产环境必须配置独立的优惠券手机号哈希密钥；AI 客服所需的 DashScope 与高德密钥必须通过环境变量或配置中心注入。
- 上线前验收以对应 TEST 文档为准。README 中的“已实现”只表示当前代码和自动化状态，不替代生产环境数据准备与验收。
