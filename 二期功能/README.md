## 乘客端福利签到

- `乘客端_福利签到_PRD.md`
- `乘客端_福利签到_TECH.md`

- `乘客端_福利签到_TODO讨论事项.md`

当前讨论结论摘要：

- 签到页先按自然月 28 天推进，每月 1 号刷新；29-31 号不能签到。
- 普通签到奖励由后端按配置计算，前端不传积分。
- 连续第 7 天奖励按 35 积分定版，不叠加普通 5 积分。
- 新增乘客积分查询接口，福利页刷新按钮和签到成功后都刷新积分总和。
- Redis Bitmap 只记录签到事实和辅助统计；MySQL 签到记录、积分账户、积分流水作为权威，表放在 `calculate` 库。
- 注销账号积分余额清零但不物理删除记录；更换手机号保留积分，因为积分跟 `customerId` 走。
- 第一期不做积分兑换/过期，只做签到获取、积分查询、注销清零。
- 第一期三张表均按普通单表设计，不做分区、不做分库分表。

当前券包与登录领券已确定的技术边界：

- 首页「券包」和个人中心「可用优惠」共用 `/app/api/v1/wallet/coupons`。
- 登录后领券弹框查询 `/app/api/v1/wallet/coupons/claimable`，领取使用 `/app/api/v1/wallet/coupons/claim`。
- 手机号领取过同一模板券后，注销再注册也不能重复领取；风控身份使用手机号哈希，不保存明文手机号。
- 生产环境必须配置 `coupon.claim-identity.phone-hash-secret`，不能使用默认 dev 值。
- 注销成功后旧账号 `UNUSED` 券置为 `INVALID`，`LOCKED` 券阻止注销。

## 乘客端个人中心-我的钱包

- `乘客端_个人中心_我的钱包_免密支付与优惠券_PRD.md`
- `乘客端_个人中心_我的钱包_免密支付与优惠券_TECH.md`
- `乘客端_个人中心_我的钱包_免密支付与优惠券_API.md`
- `乘客端_个人中心_我的钱包_免密支付与优惠券_TEST.md`

当前钱包二期已确定的技术边界：

- `wallet` 微服务负责支付宝/微信免密协议、默认免密渠道和支付单。
- `calculate` 服务负责优惠券模板、用户券、用券流水；车队营销优惠券的正式设计见本目录《车队营销优惠券_*》。
- `order` 服务通过 `trip_order_settlement` 保存订单结算、优惠、支付状态、平台服务费和承运侧收入快照。
- 银行卡、借钱、车险暂不开发，只在乘客端保留入口。
- 优惠券会影响真实金额，已确认平台服务费按乘客优惠后实付车费 5% 计算，优惠成本由发券车队承担。

## 车队营销优惠券

- `车队营销优惠券_PRD.md`
- `车队营销优惠券_TECH.md`
- `车队营销优惠券_API.md`
- `车队营销优惠券_SQL.md`
- `车队营销优惠券规则_讨论稿.md`

当前讨论结论摘要：

- 优惠券属于计价营销能力，不放入 `wallet` 库。
- 不新增 `fare_rule` 字段，优惠券方案通过 `company_id + city_code + product_code + status` 与计价规则并行匹配。
- `company_id` 在现阶段代表公司/车队/承运单元，不再引入 `fleet_id`。
- 乘客可领取自己可领的车队券，订单最终用券必须以最终承运司机对应的 `trip_order.company_id` 为准。
- 一笔订单最多使用一张券，支持自动选最优券，优惠相同优先快过期。
- 领取可以只留业务日志，使用、锁定、释放、核销、退款恢复、过期等金额动作必须留痕。
- 车队券由超管创建和停用，其他后台账号只读；线下由运营所在公司与车队沟通确认，不做系统审批流。
- 平台服务费 = 乘客优惠后实付车费 * 5%；承运侧收入 = 乘客实付车费 - 平台服务费。
- 异步派单后，锁券、核销和结算必须以最终 `trip_order.company_id` 为准，不能使用预估阶段候选司机 `company_id`。
- 账号注销后旧账号未使用优惠券应作废；已定版：手机号领取过某优惠券模板后，即使注销再注册，也无权再次领取该模板券，需以手机号哈希作为领取身份维度。
