当前钱包二期已确定的技术边界：

- `wallet` 微服务负责支付宝/微信免密协议、默认免密渠道和支付单。
- `calculate` 服务负责优惠券模板、用户券、用券流水；车队营销优惠券的正式设计见本目录《车队营销优惠券_*》。
- `order` 服务通过 `trip_order_settlement` 保存订单结算、优惠、支付状态、平台服务费和承运侧收入快照。
- 银行卡、借钱、车险暂不开发，只在乘客端保留入口。
- 优惠券会影响真实金额，已确认平台服务费按乘客优惠后实付车费 5% 计算，优惠成本由发券车队承担。

## 车队营销优惠券

- `车队营销优惠券_PRD.md`
- `车队营销优惠券_TECH.md`
- `车队营销优惠券_API.md`
- `车队营销优惠券_SQL.md`
- `车队营销优惠券规则_讨论稿.md`

当前讨论结论摘要：

- 优惠券属于计价营销能力，不放入 `wallet` 库。
- 不新增 `fare_rule` 字段，优惠券方案通过 `company_id + city_code + product_code + status` 与计价规则并行匹配。
- `company_id` 在现阶段代表公司/车队/承运单元，不再引入 `fleet_id`。
- 乘客可领取自己可领的车队券，订单最终用券必须以最终承运司机对应的 `trip_order.company_id` 为准。
- 一笔订单最多使用一张券，支持自动选最优券，优惠相同优先快过期。
- 领取可以只留业务日志，使用、锁定、释放、核销、退款恢复、过期等金额动作必须留痕。
- 车队券由超管创建和停用，其他后台账号只读；线下由运营所在公司与车队沟通确认，不做系统审批流。
- 平台服务费 = 乘客优惠后实付车费 * 5%；承运侧收入 = 乘客实付车费 - 平台服务费。
- 异步派单后，锁券、核销和结算必须以最终 `trip_order.company_id` 为准，不能使用预估阶段候选司机 `company_id`。
